# CLI Plugin

Source: https://docs.nestjs.com/graphql/cli-plugin

> warning **Warning** 本章仅适用于代码优先的方法。

TypeScript 的元数据反射系统有几个限制，例如，无法确定一个类由哪些属性组成，也无法确定给定的属性是可选的还是必需的。但是，这些约束中的一些可以在编译时解决。Nest 提供一个插件来增强 TypeScript 编译过程，以减少所需的样板代码量。

> info **Hint** 这个插件是**选择加入**。如果您愿意，可以手动声明所有装饰器，或者只在需要的地方声明特定的装饰器。

#### 概述

这个 GraphQL 插件自动执行以下操作：

- 注释输入对象、对象类型和参数类的所有属性 `@Field`，除非 `@HideField` 被使用
- 根据问号设置 `nullable` 属性（例如，`name?: string` 设置 `nullable: true`）
- 设置 `type` 属性取决于类型（也支持数组）
- 根据注释生成属性描述（如果 `introspectComments` 设置为 `true`）

您的文件名**必须具有**插件要分析的下列后缀之一： `['.input.ts', '.args.ts', '.entity.ts', '.model.ts']` (e.g., `author.entity.ts`).如果使用不同的后缀，请使用 `typeFileNameSuffix` 选项（见下文）。

根据我们到目前为止所介绍的内容，您必须复制大量代码来告诉包应该如何在 GraphQL 中声明您的类型。例如，可以按如下方式定义 `Author` 类：

```typescript
@ObjectType()
export class Author {
  @Field(type => ID)
  id: number;

  @Field({ nullable: true })
  firstName?: string;

  @Field({ nullable: true })
  lastName?: string;

  @Field(type => [Post])
  posts: Post[];
}
```

虽然这在中型项目中不是一个重要的问题，但一旦有了大量的类，它就会变得冗长且难以维护。

与 GraphQL 启用插件后，上面的类定义可以声明如下：

```typescript
@ObjectType()
export class Author {
  @Field(type => ID)
  id: number;
  firstName?: string;
  lastName?: string;
  posts: Post[];
}
```

该插件根据**抽象语法树**即时添加适当的修饰符，因此您不必分散 `@Field` 整个代码的装饰者。

> info **Hint** 该插件会自动生成任何缺失的 GraphQL 属性。如果需要覆盖它们，请使用 `@Field()` 显式设置它们。

#### 评论自省

启用注释自省功能后，CLI 插件根据注释生成字段的描述。

例如，考虑一个 `roles` 属性：

```typescript
/**
 * A list of user's roles
 */
@Field(() => [String], {
  description: `A list of user's roles`
})
roles: string[];
```

在这里，您必须复制描述。和 `introspectComments` 启用，CLI 插件提取这些注释，并自动提供属性的描述。然后可以如下声明上述字段：

```typescript
/**
 * A list of user's roles
 */
roles: string[];
```

#### 使用 CLI 插件

要启用插件，请打开 `nest-cli.json`（如果您使用 [Nest CLI](/cli/overview)) 并添加以下 `plugins` 配置：

```javascript
{
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "plugins": ["@nestjs/graphql"]
  }
}
```

使用 `options` 属性来自定义插件的行为：

```javascript
{
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "plugins": [
      {
        "name": "@nestjs/graphql",
        "options": {
          "typeFileNameSuffix": [".input.ts", ".args.ts"],
          "introspectComments": true
        }
      }
    ]
  }
}
```

这个 `options` 属性接受以下选项：

```typescript
export interface PluginOptions {
  typeFileNameSuffix?: string | string[];
  introspectComments?: boolean;
  esmCompatible?: boolean;
  debug?: boolean;
}
```

如果您不使用 CLI，而是使用自定义的 `webpack` 配置，则可以将此插件与 `ts-loader` 结合使用：

```javascript
getCustomTransformers: (program) => ({
  before: [require('@nestjs/graphql/plugin').before({}, program)]
}),
```

#### SWC 建造者

对于标准（非 monorepo）设置，使用 CLI 插件 SWC builder 要求启用类型检查，如中所述 [SWC 类型检查](/recipes/swc#type-checking).

```bash
$ nest start -b swc --type-check
```

对于 monorepo 设置，请按照 [单回购和 CLI 插件](/recipes/swc#monorepo-and-cli-plugins) 中的说明进行操作。

```bash
$ npx ts-node src/generate-metadata.ts
# OR npx ts-node apps/{YOUR_APP}/src/generate-metadata.ts
```

然后，将序列化元数据文件加载到 `GraphQLModule` 配置，如下所示：

```typescript
import metadata from './metadata.js'; // <-- file auto-generated by the "PluginMetadataGenerator"

GraphQLModule.forRoot<...>({
  ..., // other options
  metadata,
}),
```

#### 与 `ts-jest`（e2e 测试）

当您在启用此插件的情况下运行 e2e 测试时，您可能会在编译模式时遇到问题。例如，最常见的错误之一是：

```json
Object type <name> must define one or more fields.
```

发生这种情况是因为 `jest` 配置不导入 `@nestjs/graphql/plugin` 任何地方的插件。

要解决此问题，请在 e2e tests 目录中创建以下文件：

```javascript
const transformer = require('@nestjs/graphql/plugin');

module.exports.name = 'nestjs-graphql-transformer';
// you should change the version number anytime you change the configuration below - otherwise, jest will not detect changes
module.exports.version = 1;

module.exports.factory = (cs) => {
  return transformer.before(
    {
      // @nestjs/graphql/plugin options (can be empty)
    },
    cs.program, // "cs.tsCompiler.program" for older versions of Jest (<= v27)
  );
};
```

完成此操作后，将 ASTtransformer 导入 `jest` 配置文件。默认情况下（在 starter 应用程序中），e2e 测试配置文件位于 `test` 文件夹中，并被命名为 `jest-e2e.json`。

```json
{
  ... // other configuration
  "globals": {
    "ts-jest": {
      "astTransformers": {
        "before": ["<path to the file created above>"]
      }
    }
  }
}
```

如果您使用 `jest@^29` 或者稍后，使用下面的代码片段，因为前面的方法已被弃用。

```json
{
  ... // other configuration
  "transform": {
    "^.+\\.(t|j)s$": [
      "ts-jest",
      {
        "astTransformers": {
          "before": ["<path to the file created above>"]
        }
      }
    ]
  }
}
```
